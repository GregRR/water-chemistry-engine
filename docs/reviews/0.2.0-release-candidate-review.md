# Water Chemistry Engine 0.2.0 Release-Candidate Review

This record summarizes the independent two-pass review supplied for commit
`daefa6f840f1cad77559a23e6b85e935bdd0d897`. Pass 1 used open-ended discovery;
Pass 2 then checked the directed release, packaging, scientific, API, and test
questions. The reviewer worked from a fresh checkout and ran the source gates,
multi-version tests, artifact builds and installs, metadata inspection,
reproducibility comparisons, dependency/action checks, and approximately 1,100
additional scientific and semantic probes.

The review's verdict was **remediation required before 0.2.0 release**. This is
a point-in-time audit record, not a normative specification. A focused external
follow-up should evaluate the remediation before the release proceeds.

## Release-blocking findings

1. **HIGH — non-finite values could produce a false successful target result.**
   Calculation-ready concentration and treatment types rejected negative values
   but accepted NaN and infinity. The reviewer reproduced a public
   `calculate_forward_water` path in which a NaN treatment mass produced a NaN
   final concentration and a `SATISFIED` target status.
2. **MEDIUM — non-negativity was inconsistent across concentration types.**
   Exact reported concentrations, range endpoints, several reported properties,
   and therefore target criteria could accept physically invalid negative
   values.
3. **MEDIUM — valid-domain property strategies could not discover these cases.**
   Existing Hypothesis strategies deliberately excluded negative and non-finite
   values, so the invalid-domain contract needed dedicated adversarial tests.

## Additional findings and adjudication

- **Build-backend reproducibility:** the bounded `uv_build` requirement allowed
  an isolated sdist rebuild to select a different backend patch. The resulting
  wheel differed only in its generator metadata and `RECORD`, but the review
  recommended pinning the backend used for 0.2.0 and comparing direct and
  sdist-derived wheels.
- **CI action pinning:** the ordinary CI workflow used `actions/checkout@v7`
  while the release workflow already used the verified commit SHA. Aligning
  both workflows was recommended.
- **Stored-versus-calculated profile fields:** alkalinity, hardness, TDS,
  conductivity, pH, and disinfectants are preserved report data and are not
  automatically calculation inputs. The behavior was intentional but deserved
  clearer code-level documentation.
- **Module exports:** the reviewer noted the lack of broad `__all__`
  declarations. This is not a 0.2.0 release blocker: underscore naming still
  marks internal helpers, the package is explicitly pre-1.0, and the supported
  top-level consumer facade remains planned for 0.3.
- **Release tag binding:** the publishing workflow validates tag text against
  package version but does not require the tag to point at a particular reviewed
  main-branch commit. The required GitHub environment review is the deliberate
  human control for this solo-maintainer release; no workflow change was
  required.
- **Publisher settings:** the reviewer could not authenticate to GitHub or PyPI
  to inspect external settings. The maintainer and release audit separately
  verified the GitHub `pypi` environment and the pending PyPI trusted publisher
  for `GregRR/water-chemistry-engine`, `release.yml`, environment `pypi`, and
  distribution `water-chemistry-engine`.

## Positive evidence

The reviewer found the repository/package separation, distribution metadata,
artifact contents, clean installs, supported Python versions, prior-review
remediations, and core scientific invariants otherwise sound. Randomized probes
confirmed conservative unknown propagation, treatment-contribution auditability,
blend and contribution accounting, chlorine/chloramine separation from chloride,
`ND` remaining distinct from zero, explicit midpoint policy, and logarithmic pH
handling.

## Additional dependency observation

The reviewer observed that nine engine modules import `pint.Quantity` directly
while project metadata declared Pint only transitively through FermUnits. The
installed FermUnits 0.1.2 metadata requires `pint>=0.25.3,<0.26`, so no current
installation failure was present and the reviewer classified this as P3
hardening rather than a defect.

FermUnits 0.1.3 subsequently resolved the boundary gap by exporting Pint's
generic `Quantity` type through its supported package-level API while retaining
Pint as its own bounded implementation dependency. The remediation therefore
raises the engine's minimum FermUnits version to 0.1.3, imports `Q_` and
`Quantity` only through FermUnits, and removes Pint from the engine's direct
dependency metadata. This preserves real Pint quantity behavior without making
the engine depend on Pint's package-level import surface.

The public dependency was verified rather than assumed: GitHub's annotated
`v0.1.3` tag resolves to commit
`98c07d030ff85c473dfe86d16418bd7e4cfedaed`, and a no-cache Python 3.11 install
from public PyPI reports FermUnits 0.1.3, exports `Quantity`, constructs genuine
Pint quantity objects, and declares `pint>=0.25.3,<0.26` as its own dependency.
The rebuilt engine wheel and sdist each declare only
`ferm-units>=0.1.3,<0.2.0`; a fresh wheel install resolves FermUnits 0.1.3 and
Pint transitively and passes the complete public-result smoke test.

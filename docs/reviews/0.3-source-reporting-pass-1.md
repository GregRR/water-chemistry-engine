## Findings and adjudication

### F1 — P2 — `ScalarQuantity` was absent from the supported facade

**Confirmed.** The WCE-defined alias appears in public field and return
annotations throughout both the new reporting types and earlier facade types.
A strict-typed consumer could not name that policy without duplicating its
union or importing the unsupported `quantity_types` module.

The remediation exports `ScalarQuantity` through the package root and adds it
to the independently maintained test and documented inventory. FermUnits
continues to own `Quantity`, `PHValue`, `Q_`, and the registry; exporting this
WCE-specific alias does not duplicate that dependency boundary.

### F2 — P2 — the published pH migration lacked compatibility guidance

**Confirmed.** The published 0.2.0 `TargetWaterProfile.ph` field accepted a
float, while the reviewed candidate requires `PHValue`. The changelog described
the semantic migration but did not label the source incompatibility or show the
required `ph=PHValue(7.0)` replacement.

The focused second pass broadened this finding to include the published
`ReportedPH` contract. Its convenience constructors remain source-compatible,
but its stored fields and `calculation_value` now return `PHValue`, and direct
dataclass construction requires semantic values. The remediation documents
both distinct migration paths in the changelog and consumer guide.

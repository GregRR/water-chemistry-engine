## Published pH compatibility finding

Pass 2 verified that the migration has two distinct compatibility paths:

- `ReportedPH.exact()`, `.range()`, and `.average()` continue accepting numeric
  arguments, but the stored fields and `calculation_value` now produce
  `PHValue`; direct field construction also requires `PHValue`.
- `TargetWaterProfile.ph` has no convenience constructor, so every 0.2 caller
  passing a float must change to `ph=PHValue(...)`.

The remediation must disclose both paths explicitly rather than presenting the
change as an undifferentiated implementation detail.

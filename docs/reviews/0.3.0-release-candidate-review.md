# Water Chemistry Engine 0.3.0 — Release-Candidate Review

This record summarizes the independent two-pass review of release candidate
`c7afac50af847eefcb7a2c70419e1f8eabb6d99b` against the published `v0.2.0`
baseline and the focused follow-up review of documentation remediation commit
`15703392e3b031d9ba7137f0481ce849eedf5496`.

The reviewer used fresh checkouts pinned to the requested commits and did not
modify, commit, tag, publish, approve a deployment, create a release, or alter
GitHub or PyPI configuration. This is a point-in-time audit artifact, not a
normative specification.

The review found no scientific, numerical, consumer-API, compatibility,
packaging, reproducibility, or clean-install defect. Its final verdict was
**PASS WITH CONDITIONS**, with the candidate explicitly cleared to advance to
final release preparation subject to the owner-controlled release gates below.

## Findings and disposition

- **P2 — accepted controlled pre-publication condition:** the README links to
  the version-pinned `v0.3.0` consumer API document before that tag exists. The
  reviewer confirmed that the tag-triggered release workflow cannot publish
  until the remote tag exists and its version matches the package version.
  Keeping the versioned links avoids allowing the immutable PyPI 0.3.0 page to
  drift with later `main` documentation. The owner must verify the links after
  pushing the tag and before approving the protected `pypi` deployment.
- **P3 — closed:** commit
  `15703392e3b031d9ba7137f0481ce849eedf5496` presents Python 3.11 through
  3.14 compatibility as a current project-wide fact and labels the listed
  deterministic forward-calculator capabilities as established in 0.2. The
  focused follow-up found the wording accurate and consistent with the active
  roadmap, design, changelog, and contributor instructions.

No new finding was introduced by the remediation.

## Scientific and consumer-contract result

The reviewer independently exercised a strict-typed external-consumer probe
using only FermUnits and package-root Water Chemistry Engine imports. It could
construct source/provenance and target inputs, run the forward calculator, and
interpret the result graph without importing engine internals or Pint.

The review confirmed exact parity among the 93-name package `__all__`, the
hard-coded API contract test, and the documented inventory. It also verified:

- semantic FermUnits `PHValue` migration for reported and target pH;
- no arithmetic midpoint for a pH range;
- calculated working-water pH remains explicitly unsupported;
- unknown and `ND` inputs remain distinct from zero;
- source-resolution policy remains explicit;
- ranges, bounds, statistics, reporting bases, disinfectants, water identity,
  source documents, and result context retain their semantics and provenance;
  and
- generalized treatment-material behavior remains future 0.4 work.

## Packaging and installation result

The reviewer built and inspected the wheel and sdist from candidate `c7afac5`.
Both artifacts reported:

- distribution `water-chemistry-engine`;
- version `0.3.0`;
- Python requirement `>=3.11`;
- dependency `ferm-units>=0.1.3,<0.2.0`;
- the intended Python 3.11 through 3.14 classifiers;
- the renamed repository URLs; and
- the MPL-2.0 license expression and packaged license file.

Neither artifact contained the obsolete import package, old application,
caches, environments, or local build artifacts. A wheel independently rebuilt
from the sdist was byte-identical to the normal wheel, with SHA-256
`597e0d5d806aa734c2fafafaa6fe0650a039b1c1eaba62a6b5889036f0f5d193`.

The replacement candidate changed only README prose, which is embedded in the
artifact long description; its final artifact hashes are therefore expected to
differ and are established separately by the final release gate.

A clean Python 3.11 installation outside the checkout resolved the import from
the environment's `site-packages`, reported version `0.3.0`, and ran the README
quickstart verbatim with the documented output:

```text
60.0 milligram / liter
```
